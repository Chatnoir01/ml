# Phase 2V-T2 — prespecified ideal-permutation oracle control for ToySPN ciphertext distinguishers
**Pre-execution scientific registration: 2026-11-06, before any T2 oracle-sampled AUC outcome. DRAFT, stacked on #171. No neural training or Phase 2U scoring.**

## Falsifiable question

Phase 2V-T1 found that a fixed four-byte XOR-difference count-based distinguisher trained on the educational 32-bit four-round ToySPN retained an AUC around 0.68 on held-out S-Boxes and a precommitted alternate key schedule. **Is that pair-label signal a feature of ToySPN's round construction rather than a generic feature of the input pair-generation/labeling method?**

Run an exactly matched **random bijection on the 32-bit block domain** (an *ideal random permutation oracle*, sampled lazily on actually queried points). Each oracle maps every repeated input to the same output and distinct inputs to distinct outputs. This is NOT a random independent function, which could collide and would be an inappropriate block-cipher comparator. See [PRP definition](https://crypto.stanford.edu/pbc/crypto/prp.html) and [lazy permutation sampling](https://eprint.iacr.org/2023/770).

Random-oracle simulations are generated by Python's deterministic `random.Random` seeded by a published domain-separated SHA-256 digest. This provides a **reproducible sampled ideal-permutation experiment**, not cryptographic randomness, physical independent attestation or an exhaustive average over all 2^32! permutations.

## Reproducibly sampling uniform-on-queried-points 32-bit permutations

Set domain size N = `2**32`. Exactly one **persistent** random permutation oracle per `(evolution_seed, original S-Box fingerprint, key arm)`, for **9×20×2=360** oracle objects. Across all T seeds/differences, re-use each oracle mapping: a repeated plaintext input under the same S-Box identity and key arm always has the same sampled output.

For each unqueried 32-bit plaintext `x`, choose one unused 32-bit output uniformly by a **sparse Fisher–Yates dynamic swap table** (an efficient uniformly sampled *partial permutation* with lazy sampling), and store `x -> y`. Repeated `x` returns the prior `y`. No output may repeat across different plaintexts in the same oracle. Use Python `random.Random(int.from_bytes(SHA256(b"phase2v-t2-uniform-32bit-prp-v1|" || evol_decimal || "|" || sbox_fingerprint_ascii || "|" || arm_ascii),"big"))` for the reproducible pseudo-random stream; arm names exactly `source` and `alternate`, with a fresh independent map for each. The two arms are analogous to two independently sampled key-indexed ideal permutations rather than the same permutation under multiple keys.

For each source cell, regenerate the EXACT original plaintext pair schedule from T1, and send both endpoints of each pair through the persistent oracle for that (evolution,SBox,arm). The same original 20-SBox T1 source ToySPN encryption is recomputed in parallel for integrity checks. Lock iteration order: evolution seeds in listed ascending order, differences (1,256), T seeds (776003,776097), S-Boxes by original SHA3 fingerprint, train/validation/test order, each pair's first then second endpoint. This makes the entire experiment byte-reproducible.

**Independent sampler tests before any scientific outcome:** on a tiny 8-bit test domain, full-domain enumeration of the sampled permutation is bijective; repeat queries idempotent; with two different seeds most maps differ; for 32-bit original oracles, inspect size of sampled domain, one-to-one outputs, no input/output collision of distinct entries and label/plaintext parity with source.

## Identically preregistered learning and scoring on each cipher family

For **each cell and cipher family separately**, train the same very weak four-byte XOR-difference naive Bayes table with **Laplace pseudocount alpha=1** on **ONLY 4,200 original-key/seen-SBox training examples**. The ideal-control table learns from ideal-control train ciphertext XOR values; it does NOT reuse the ToySPN table. Neither model may access alternate-key or held-out S-Boxes at fit time. Compute four baselines for both families on four panels:
1. constant-score null (tie-aware AUC 0.5);
2. fixed **negative** 32-bit XOR Hamming weight;
3. fixed count of ZERO bytes of the 32-bit ciphertext XOR;
4. the one fitted (separately in each family) four-byte Laplace-1 class-conditional frequency log-likelihood ratio (the T1 histogram).

Do NOT flip signs/choose best baseline after data. Evaluate all **36 × 4 = 144** registered test panels for **both ToySPN and ideal-permutation** => **288** AUC panel rows, each with exact four method AUCs; keep each pair of related rows in the same cohort. No neural model fit or S-Box generator optimization occurs. Do not increase the number of oracle replicates after viewing outcomes.
